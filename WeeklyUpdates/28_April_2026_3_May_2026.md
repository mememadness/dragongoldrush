## Week 14: 28 April — 3 May 2026

**Focus:** v1.0.0 Release, Admin App Service Migration, Cost Optimisation Wrap-up, Release Pipeline Hardening

### Release — v1.0.0
- **Version bump** to 1.0.0 (PR #355) — first major tag, marking the point where the credit system, Dragon payments, V2 sprite library, and rebuilt admin dashboard are all on `main` together
- **Tagged `v1.0.0-rc.3`** and promoted to pre-prod mainnet UAT for sign-off

### Game Client
- **What's New Popup (PR #354, #357):** Version-gated welcome dialog auto-opens when the runtime version differs from the dismissed version. Surfaces four highlights (Pay with CKB or Dragon, earn-by-play credits, 2-special-item-per-level cap, V2 sprite rework) with a deep-link CTA into the shop hub
- **Popup layout polish (PR #357):** Title word-wrap, sprite-aware modal sizing so the button sprite stays inside the gold border, checkbox repositioned clear of the button artwork, single bottom row of OK + Buy Credits CTAs

### Infrastructure / Cost Optimisation
The cost-reduction track from last period landed its biggest single saving this week.

- **Admin Dashboard → App Service Linux (PR #352):** Migrated across all three environments (dev, pre-prod, prod). Easy Auth header behaviour is byte-identical between Container Apps and App Service so no middleware changes were needed
- **Per-env Container Apps Environments destroyed:** The managed Standard Load Balancer that comes with each CAE (~$18–20/mo) is gone in dev, pre-prod, and prod
- **Backend plan strategy:** Shared backend B1 plan in dev/pre-prod ($0 marginal); dedicated `plan-dragon-admin-prod` B1 in prod for blast-radius isolation around CKB hot-wallet operations
- **Cosmos hardening:** `enable_cosmos_public_network_access` parameterised — `false` in prod (private-endpoint-only)
- **Test environment fully removed (Phase 5):** `rg-dragon-test` resource group, Entra app + groups, tfstate blob, and all code/CI/docs references purged. The legacy Container App + CAE resources are commented out (recoverable) rather than deleted, so the migration is reversible if needed
- **Combined saving:** ~$80–100/mo recurring Azure spend eliminated when stacked with the test-env removal from the previous period

### Level Redesign (In Progress)
A major in-flight workstream not yet reflected in merged PRs — the existing level set is being rebuilt around the V2 sprite library and the new level schema.

- **Visual refresh:** Levels reauthored against the V2 treasures, jewel variants, and reworked blockers so the existing content matches the new art direction
- **Mechanical refresh:** Chained treasures, irregular shapes, and shape variants (now possible thanks to the robust gravity engine) being woven into the existing progression
- **Story Mode foundation:** This redesign work doubles as the production pipeline shake-down for the larger Story Mode content tranche targeting June

### CI/CD & Release Pipeline
- **IP-allowlist fix (PR #356):** Backend deploy was silently failing on every release because the existence check looked for `ip_address` (snake_case) while Azure returns `ipAddress` (camelCase). Surfaced during the v1.0.0-rc promote. Fix accepts both keys and adds an `|| true` safety net so duplicate-rule responses are treated as success
- **Affected workflows:** `promote-environment.yml`, `azure-appservice-deploy.yml`
